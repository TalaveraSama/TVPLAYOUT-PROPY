# TVPlayout PRO V22.2.7

## Bug crítico: los cortes no se veían en el monitor

El usuario reportó: cuando se dispara un corte (hora exacta o tanda
automática), el panel de la consola SÍ cambiaba al nuevo clip
(fila nueva con estado "AL AIRE", fila vieja con "CORTADO"),
**pero el monitor seguía mostrando el clip anterior**.

El playout local estaba lógicamente bien (la barra de progreso
reflejaba la duración del nuevo clip), pero el frame de video en
pantalla era del clip anterior.

## Causa raíz

`MPVPlayer.play()` mandaba 7 `set_property` ANTES del comando
`loadfile`:

```python
set_property("aid", ...)
set_property("sid", ...)
set_property("start", ...)       # ← problema
set_property("loop-file", ...)
set_property("volume", ...)
set_property("mute", ...)
set_property("pause", False)     # ← problema
command(["loadfile", path, "replace"])
```

Tres problemas conocidos de mpv con este patrón:

1. **`set_property("start", "none")` se conservaba del archivo
   anterior** (issue #15544 del repo oficial de mpv).

2. **`set_property("pause", false)` ANTES del loadfile** dejaba
   al nuevo archivo en estado inconsistente: mpv cambiaba el path
   "activo" pero el framebuffer seguía siendo del archivo anterior
   hasta que llegara el primer frame decodificado del nuevo.

3. **Las propiedades se procesan en cola FIFO** pero pueden
   "pisarse" entre el momento que se mandan y el momento que se
   aplican al nuevo archivo.

## El fix

Reemplazar los `set_property` separados por **opciones embebidas
en el comando `loadfile`**, que mpv garantiza que se aplican en
orden ANTES de decodificar el primer frame del nuevo archivo:

```python
cmd = ["loadfile", path, "replace",
       "aid=auto", "sid=no",
       "start=+0.000", "loop-file=no",
       "pause=no", "volume=100.0", "mute=no"]
self.command(cmd)
```

Resultado: volume, mute, pause y start se aplican al NUEVO archivo
de forma atómica. No hay ventana donde el archivo nuevo esté
"cargándose" con propiedades del viejo.

## Cómo actualizar

1. `git pull origin arena/01a07acb-tvplayout-propy`
2. `build_exe.bat` (o re-ejecutá con `python main.py`)
3. Reemplazá `TVPlayoutPRO.exe`

## Compatibilidad

- Sin migración de BD.
- Sin cambios visibles en la UI.
- El cambio está en el método `play()` de `MPVPlayer`. Si tenés
  scripts propios que llamen `set_property` antes de un loadfile,
  no se ven afectados (sólo se cambió la implementación interna).

## Pruebas

18/18 tests automatizados. El test de "reaplicar volumen/mute en
play()" se actualizó para verificar que las opciones estén embebidas
en el loadfile (en lugar de `set_property` separados).
