# TVPlayout PRO V22.2.4

## El bug que arregla: loop infinito de "drift" en el RTMP

En v22.2.3, cuando prendías el RTMP con el playout local
reproduciendo, el log mostraba un loop así:

```
RTMP drift 2.41s (mpv=0.00s, ffmpeg_est=2.41s) — realineando
RTMP drift 4.42s (mpv=0.00s, ffmpeg_est=4.42s) — realineando
RTMP drift 5.90s (mpv=0.00s, ffmpeg_est=5.90s) — realineando
... (repite cada 2 segundos, sin parar)
```

Y en el monitor veías el video avanzando, pero la barra de
progreso y el contador "POSICIÓN" se quedaban en 00:00:00.

## Por qué pasaba

El watcher de drift (que está en `app/main_window.py:1685`) leía
`self.player._time` para saber la posición del playout local.
`self.player._time` se actualiza cuando mpv manda el evento
"property-change" con `name="time-pos"`.

**En algunas builds de mpv, o en condiciones específicas de la PC
del operador, ese evento no se emite aunque el video SÍ esté
reproduciendo.** El video avanzaba (lo veías en el monitor), pero
`self.player._time` quedaba en 0.

Mientras tanto, `ffmpeg_est` SÍ avanzaba (porque el FFmpeg real
sí estaba emitiendo frames). Resultado: `drift = 0 - N = N`,
siempre creciente, siempre realineando, cada 2 segundos.

19 realineaciones en 38 segundos. Microcortes constantes en el
stream.

## El fix

`PlayoutController.elapsed` ahora estima la posición del playout
local con el **reloj de pared** cuando mpv no está reportando
time-pos:

```python
@property
def elapsed(self):
    if self._pos > 0:
        return self._pos
    if 0 <= self.onair < len(self.items) and self._started_at > 0 and not self.paused:
        return max(0.0, time.time() - self._started_at)
    return self._pos
```

Lógica:
- Si mpv está reportando (`_pos > 0`), usamos ese valor (lo más exacto).
- Si mpv NO está reportando (`_pos == 0`) pero hay algo al aire y no
  estamos en pausa, estimamos con `now - _started_at`.
- Si no hay nada al aire, devolvemos 0.

El watcher de drift y `_rtmp_start` ahora usan `self.ctrl.elapsed`
en vez de `self.player._time`. El log pasa de esto:

```
RTMP drift 5.21s (mpv=0.00s, ffmpeg_est=5.21s) — realineando
```

a esto (cuando están sincronizados, no hay log de drift):

```
(sin mensaje — drift dentro del umbral)
```

## Cómo actualizar

1. `git pull origin arena/01a07acb-tvplayout-propy`
2. Doble clic en `build_exe.bat` (si no tenés el .exe).
3. Reemplazá el `TVPlayoutPRO.exe` viejo por el nuevo.

O si usás la rama con `python main.py`, simplemente reinciá la app.

## Compatibilidad

- Sin migración de BD.
- Sin cambios en la UI.
- La barra de progreso del playout local puede mostrar 0 si mpv
  no está reportando, hasta que mpv mande un `time-pos` válido.
  El playout sigue funcionando; lo que mejora es el comportamiento
  del RTMP.

## Pruebas

- 18 tests automatizados (todos pasan), incluyendo uno nuevo que
  verifica que el watcher usa `self.ctrl.elapsed`.
